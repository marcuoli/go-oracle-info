# Code management

The private Gitea repository owns source history; the module path is the public distribution coordinate. Bootstrap history contains one empty root commit; implementation is reviewed on its issue branch.

Use `feat`, `fix`, `docs`, `refactor`, `test`, `build`, `security` or `chore` issue titles, exactly one matching type label and accurate area labels. Maintain `## Validation and acceptance` with evidence-backed checkboxes. A feature is not complete merely because a subset of tests passed. Preserve unmet acceptance and the exact remaining next action.

Permanent source stays on cloud-backed I:. Record issue-owned V: worktree paths and administrative directories at creation. Remove completed temporary worktrees through Git only after authorized integration, canonical synchronization and preservation of unique files/evidence. Verify registration and both filesystem paths before closure. Preserve private inputs, credentials, unrelated edits and immutable history.

Use conventional immutable module tags. No public mirror, release or consumer migration is implied by an uncommitted prototype. Preserve publication/adoption proof separately from local test evidence.
